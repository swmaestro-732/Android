# 계획 생성 진입점과 카드 placeholder

- 브랜치: `feat/SCRUM-735-plan-create-placeholder`
- 변경: 계획 목록이 비면 `계획 생성하기` 카드(140dp 높이, 점선 테두리, 28dp 추가 아이콘)를 표시한다. 설명은 `가 보고 싶은 곳을 모아 계획을 세워 보세요`다. 카드 전체를 누르면 기존 `/courseCreate`에 `isPlan=true`로 진입한다.
- 이미지가 없는 계획 카드(`plan-` 목록 ID)에 36dp 접은 지도 아이콘(`contentAccent`)과 장소 썸네일과 같은 선형 그라데이션 배경(`bgAccentSubtle` → `bgDefaultLevel1`, 좌상단 → 우하단)을 표시한다. 기존 회색 빈칸을 대체하며 코스 카드의 이미지 정책은 바꾸지 않는다.
- 서버 요청·계획 저장 조건·목록 오류 재시도는 기존 계약을 사용한다.

## 화면 확인 — 2026-11-03

실제 에뮬레이터에서 최신 Compose 구현을 촬영했다. 마이 프로필 실조회가 실패하여 임시 debug 진입점으로 예시 프로필·계획 상태를 주입했다. 임시 진입점은 커밋에서 제외했다. 최초 촬영 APK는 appVersionCode=99999, 그라데이션 보완 캡처는 999999이며 출시 버전 변경이 아니다.

1. [빈 계획 목록](empty.png): 예시 프로필·계획 0개, 생성 카드 표시.
2. [계획 카드](filled.png): 예시 계획 2개, 최종 그라데이션 배경·지도 아이콘.
3. [생성 버튼 클릭 결과](create.png): 실제 버튼에서 `/courseCreate`·`isPlan=true` 전달을 확인하고 MainActivity의 기존 `계획하기` 화면 진입을 확인했다. 장소 추가·저장 요청은 제출하지 않았다.

실데이터 계획 조회·생성 저장 왕복은 미검증이다. Courmy UI Flow의 기존 실데이터 이미지는 유지하고 예시임을 명시한 최신 캡처를 함께 기록한다.

- 미갱신: 마이 → 계획 탭의 실제 빈 목록 화면과 실제 생성된 계획 카드 목록 화면. 에뮬레이터에서 마이 프로필 조회가 실패하여 두 상태에 정상 진입하지 못했다. 위 empty.png와 filled.png는 이 두 상태의 예시 데이터 캡처이며 실서버 조회 성공의 증거가 아니다.
- 미촬영: 계획 저장 완료 후 마이 → 계획 목록에 돌아온 화면. 실제 장소 추가와 저장 요청을 제출하지 않아 해당 상태에 진입하지 않았다. create.png는 생성 진입만 검증한다.
